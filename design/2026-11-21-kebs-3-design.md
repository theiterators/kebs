# kebs 3 — design

Status: draft for maintainer review · 2026-11-21

## 1. Intent

Rewrite kebs' macros on [hearth](https://github.com/kubuszok/hearth) — or delegate to
[kindlings](https://github.com/kubuszok/kindlings) where a kindlings module already does the job — so that:

- **macros are faster** to compile (no inline/`Mirror` recursion, no implicit-search chains) and the generated code is
  faster at runtime (no `productIterator` zipping, no `Tuple` allocation, no per-site anonymous classes — issue #417);
- **there is one implementation per macro** shared by Scala 2.13 and Scala 3, instead of two that drift apart;
- **behaviour is the same on both Scala versions** (today it is not — see §4.2).

While the macros are being rewritten, kebs 3 also closes cheap feature gaps, unifies how JSON modules name fields and
enum values, and adds ADT support to the JSON modules. Because the Scala 3 floor moves (see §3), this is a major
release: **kebs 3.0**.

Before kebs 3 work lands on master, kebs **2.3.0** is cut with dependency bumps only, as the (likely) last 2.x minor.

## 2. Goals, non-goals, anti-goals

**Goals**

1. Every macro kebs owns is written once on hearth, cross-compiled for 2.13 and 3.
2. circe and scalacheck derivation delegate to kindlings; a new `kebs-jsoniter` module is built on kindlings.
3. The current test suites keep passing on both Scala versions; they are the behavioural spec (see §6).
4. Scala 2 vs Scala 3 inconsistencies listed in §4.2 are removed.
5. The gaps listed in §4.3 are filled.
6. One naming vocabulary for field names and enum values across all modules (§5.3).
7. JSON modules (circe, spray-json, play-json, jsoniter) derive case classes **and** sealed hierarchies the same way,
   configured the same way (§5.4).

**Non-goals**

- tagged-meta (Scala 2 macro annotation) and jsonschema (scala-jsonschema is Scala 2 only) are not rewritten; they stay
  Scala 2 only, unchanged apart from build changes.
- slick-pg issues (#4, #5, #6, #276) are not addressed.
- PATCH semantics (distinguishing absent vs `null` fields) are not exposed by kebs.
- No changes to `instances`, `opaque`, `tagged`, `slick`, `baklava` beyond what build/dependency/enum-naming changes
  require.

**Anti-goals** (a release that does these is a failure even if it compiles)

- **Silent wire-format changes.** A kebs 2 user upgrading to kebs 3 must get the same JSON (and the same DB/HTTP enum
  strings) unless the change is deliberate and listed in the migration guide. Defaults are chosen to preserve today's
  output per module.
- Users having to rewrite call sites for things that did not change conceptually: the existing entry points
  (`KebsCirce`, `circe.snakified`, `sprayjson.capitalized`, `enums.uppercase`, `KebsArbitrarySupport`,
  `CaseClass1ToValueClass`, …) keep their names and roles.
- Worse error messages than today for a missing instance.

## 3. Constraints

- **Scala versions: 2.13.18 and 3.9.0 (LTS).** kindlings 0.4.0's Scala 3 artifacts are built with 3.8.4, so the kebs
  Scala 3 floor rises from 3.3 to 3.9. Verified: kindlings-circe-derivation 0.4.0 compiles and runs from a 3.9.0 build.
- **JDK 17+.** Scala 3.8+ requires it. CI moves from JDK 11+17 to JDK 17+21.
- **hearth 0.4.5, kindlings 0.4.0.** kindlings 0.4.0 depends on hearth 0.4.5; kebs must depend on exactly the hearth
  version its kindlings version uses (they run inside the compiler, an evicted mismatch can break macro expansion).
  Policy: bump hearth and kindlings together.
- hearth is pre-1.0 and becomes a transitive dependency of every kebs user (via kebs-core).
- Cross-compiled hearth macros still need a small per-version entry file (`scala-2/` macro bundle, `scala-3/`
  `inline … = ${…}`), and the `hearth-cross-quotes` compiler plugin on Scala 3. The macro logic is shared.
- Platforms stay as today (core/circe/http4s/… on JVM+JS+Native, play-json JVM+JS, others JVM). hearth and the used
  kindlings modules are published for all three platforms.
- Binary compatibility: kebs 3.0 breaks it deliberately; MiMa is disabled for 3.0.0 and re-enabled with
  `tlMimaPreviousVersions := Set("3.0.0")` afterwards.
- Generated docs (`docs/*.md`) are compiled by mdoc into the website; `ci.yml` is generated by sbt-github-actions
  (never hand-edit; regenerate from build.sbt). The website workflow only runs on master.

## 4. Scope

### 4.1 Macro inventory and where each goes

| Module | Today (2.13 / 3) | kebs 3 |
|---|---|---|
| core `ValueClassLike` (`CaseClass1ToValueClass`) | whitebox macro / `Mirror.ProductOf` + `productElement(0).asInstanceOf` | hearth macro |
| enum | `Enumeration` only / Scala 3 `enum` only; `KebsValueEnum` Scala 3 only | hearth macro (`Enum` view) |
| enumeratum | `Companion.values` / `Mirror` inline recursion | hearth macro, `Companion.values` on both |
| spray-json | own macro (spray `jsonFormat` ≤22, hand-rolled >22) / `Mirror` + runtime zip | hearth macro |
| play-json | none (flat/enum/instance formats only) | **new** hearth macro (issue #384) |
| circe | own macro + circe-generic `AutoDerivation` + generic-extras >22 / circe `ConfiguredDecoder` | kindlings-circe-derivation |
| jsoniter | — | **new** module on kindlings-jsoniter-derivation (issue #255) |
| scalacheck | magnolify / scalacheck-derived | kindlings-scalacheck-derivation |
| jsonschema, tagged-meta | Scala 2 only | unchanged |
| akka-http | Scala 2 only, Akka 2.6 | **dropped** (pekko-http replaces it) |

### 4.2 Inconsistencies to remove

1. `ValueClassLike` on Scala 3 constructs via `Mirror.fromProduct` (the constructor), bypassing a validating
   companion `apply`; Scala 2 calls `apply`. → Both call the companion `apply` (verify a test exists; add one).
2. enum: Scala 2 handles only `scala.Enumeration`, Scala 3 only `scala.reflect.Enum`; value enums only on Scala 3. →
   `KebsEnum` handles `Enumeration` on both versions and `enum` on Scala 3; `KebsValueEnum` on both versions for
   sealed hierarchies / enums extending `ValueEnumLikeEntry` (today's Scala 3 bound, now also on 2.13).
   **Plain sealed hierarchies of case objects do not get an `EnumLike` automatically** (decided 2026-11-21 after
   review): enumeratum entries are such hierarchies too (the two implicits would compete), and it would silently turn
   `{"Red":{}}` into `"Red"` for circe users. They stay ADTs; users who want enum strings use enumeratum, `Enumeration`,
   a Scala 3 `enum`, or the ADT's `constructorNaming` with case objects.
3. enumeratum on Scala 3 ignores the user's `values` and fails on nested sealed hierarchies. → `Companion.values` on
   both.
4. circe: Scala 2 auto-derives sealed traits, Scala 3 only case classes; snake_case comes from kebs' `snakify` on 2 and
   circe's renaming on 3. → kindlings on both, given kebs' naming functions.
5. spray-json: `jsonFormatRec` is a real lazy format on 2, an alias on 3; >22 fields hand-rolled on 2 (and there it
   drops *any* `JsNull` field, not only `None`); Scala 3 zips lists at runtime. → One hearth macro; recursion handled
   inside the macro (`jsonFormatRec` kept as a deprecated alias of `jsonFormatN`).
6. scalacheck: different generators per version. → kindlings on both.
7. Tests: enum-related tests use enumeratum on Scala 2 and native enums on Scala 3. → Shared tests (`src/test/scala`)
   exercising sealed-trait enums and enumeratum on both versions; Scala 3 `enum` tests stay in `scala-3/`.

### 4.3 Gaps to fill

- play-json auto-derivation (#384) — §5.4.
- jsoniter-scala module (#255) on kindlings. Contributor PR #531 (built on jsoniter's own macros) is closed with
  thanks and credit in the release notes; its tests are reused where they fit.
- http4s: value-enum path matchers and `QueryParamDecoder` (parity with http4s-stir/pekko-http).
- pureconfig: `EnumLike`, `ValueEnumLike` and `InstanceConverter` readers/writers.
- scalacheck: `Arbitrary` for `EnumLike`, `ValueEnumLike` and `InstanceConverter` types.
- `EnumLike` lookups (`withNameInsensitiveOption`, upper/lower variants) use precomputed maps instead of linear scans.
- #417 is closed by the rewrite (no anonymous classes duplicated per inline site).
- #410 (sbt-typelevel) is already done — close it.

## 5. Design

### 5.1 Delivery

**Approaches considered**

- **A. One module per PR, straight into master** (picked). First PR switches the build and ports core; master
  becomes 3.0-SNAPSHOT; 2.x fixes come from `series/2.x` cut at v2.3.0. Small reviewable PRs, both Scala versions
  green at every step.
- B. Same PRs into a long-lived `kebs-3` branch merged at the end. Keeps master releasable as 2.x but needs rebasing.
- C. One big PR. Fast to start, hard to review and to bisect.

**Order**

0. **2.3.0 release** (on master, before any kebs 3 change): merge open Steward PRs except doobie RC13/RC14 (#556,
   #611 — package relocation, breaking) and scala-library 3.10 (#604 — 2.x stays on 3.3 LTS). Set
   `tlBaseVersion := "2.3"`, `tlMimaPreviousVersions := Set("2.2.2")`, README versions; maintainer confirms before
   merges and before pushing tag `v2.3.0`. Cut `series/2.x` from the tag.
1. **Spike** (throwaway, worktree): see §7.
2. **PR: build + core** — Scala 3.9.0, JDK 17/21, `tlBaseVersion := "3.0"`, MiMa off, hearth + cross-quotes plugin
   wiring, drop akka-http, doobie RC14 migration (`org.typelevel.doobie`), core `ValueClassLike` on hearth.
3. **PR: enum + enumeratum** on hearth; `EnumLike` map-based lookups; shared enum tests.
4. **PR: naming** — `Naming`, `EnumNaming`, `JsonConfig` in core (§5.3); enum codecs in every module (circe, spray,
   play, doobie, baklava, pekko-http, http4s, http4s-stir, slick) moved onto `EnumNaming`.
5. **PR: spray-json** hearth macro (§5.4).
6. **PR: play-json** auto-derivation (§5.4).
7. **PR: circe** on kindlings (§5.4).
8. **PR: jsoniter** new module (§5.4).
9. **PR: scalacheck** on kindlings + enum/`InstanceConverter` arbitraries.
10. **PR: small gaps** — http4s value enums, pureconfig enum/`InstanceConverter`.
11. **Release** — docs for every module, a "Migrating to kebs 3" page, README; `v3.0.0-RC1`, then `v3.0.0`.

Each PR keeps every existing test green on 2.13 and 3.9 (JVM; JS/Native where the module has them).

### 5.2 Build

- `scala_3 = "3.9.0"`; drop `-Xmax-inlines 64`/`-Yretain-trees` if no longer needed once inline derivation is gone.
- Modules containing hearth macros (core, enum, enumeratum, spray-json, play-json) get `"com.kubuszok" %%% "hearth"` and,
  on Scala 3, `compilerPlugin("com.kubuszok" % "hearth-cross-quotes_3" % hearthV)`; on 2.13 they keep
  `scala-reflect`/`scala-compiler % provided`.
- Layout per hearth macro: shared logic in `src/main/scala/.../internal/compiletime/*MacrosImpl.scala`
  (`trait … { this: MacroCommons => … }`), entry points in `src/main/scala-2/…Compat.scala` and
  `src/main/scala-3/…Compat.scala`.
- `disableScala(List("3"))` stays for jsonschema and tagged-meta; examples stay 2.13-only.

### 5.3 Naming (core)

A single vocabulary used for JSON field names, ADT case names and enum values, in `pl.iterators.kebs.core.naming`:

```scala
final case class Naming(apply: String => String) { def andThen(that: Naming): Naming }
object Naming {
  val identity, snakeCase, screamingSnakeCase, kebabCase, camelCase, pascalCase, lowercase, uppercase: Naming
  def custom(f: String => String): Naming
}
```

- Word splitting lives in one place and reproduces today's `SnakifyVariant.snakify` exactly (so snake_case output does
  not change for Scala 2 users); `capitalize` ≡ `pascalCase`. `SnakifyVariant`/`CapitalizeVariant` become deprecated
  forwarders.
- **Enum values:** `final case class EnumNaming(naming: Naming, caseInsensitive: Boolean = true)`. Every enum codec in
  every module takes an implicit `EnumNaming`; the companion holds the default (`identity`, case-insensitive), so a
  user's implicit in lexical scope wins. Encoding writes `naming(name)`; decoding matches the mapped name (case-
  insensitively by default — today the identity decoder is case-insensitive and upper/lower are strict; making all
  lenient only accepts more input). The existing `enums.uppercase` / `enums.lowercase` objects become presets; new
  presets for `snakeCase`, `screamingSnakeCase`, `kebabCase`.
- **JSON config:** one case class shared by all JSON modules:

  ```scala
  final case class JsonConfig(
    fieldNaming: Naming,
    constructorNaming: Naming,     // ADT case names
    noneHandling: NoneHandling,    // WriteNull | Omit
    useDefaults: Boolean,          // fill missing fields from case-class defaults
    discriminator: Option[String]  // None = wrapper object {"Case": {...}}
  )
  ```

  Each JSON protocol trait exposes an overridable `implicit def kebsJsonConfig: JsonConfig` with that module's default;
  the presets (`snakified`, `capitalized`) override it. Users customise by overriding it in their protocol object, or
  per type by passing a config to an explicit derivation method. (This replaces the separate `FieldNaming` /
  `NoneHandling` implicits floated during discussion — one implicit is simpler to resolve unambiguously on 2.13.)
- **Module defaults preserve today's output:**

  | | fieldNaming | noneHandling | ADTs |
  |---|---|---|---|
  | circe | identity | WriteNull | wrapper (as circe-generic on 2.13 today) |
  | spray-json | identity | Omit (`NullOptions` → WriteNull) | wrapper |
  | play-json | identity | Omit (Play's convention) | wrapper |
  | jsoniter (new) | identity | WriteNull (kindlings default, same as circe) | wrapper |

  `constructorNaming = identity`, `useDefaults = false`, `discriminator = None` everywhere.

### 5.4 JSON modules

Common rules for all four:

- **Flatness is owned by kebs.** A single-field case class is encoded as its field only when a `ValueClassLike` is in
  scope (`CaseClass1ToValueClass` mixed in), exactly as today. kindlings' own `AnyVal` unwrapping is turned off
  (`unwrapValueClasses = false`) so `AnyVal` case classes without `CaseClass1ToValueClass` still encode as objects.
- **Existing instances win over kebs' auto-derivation — for the root type and for every field type.** That covers
  user instances in companions (`Json.format`, circe `deriveEncoder`, Scala 3 `derives`, enumeratum's `CirceEnum` /
  `PlayJsonEnum`, …), instances in lexical scope, and kebs' own flat / `InstanceConverter` / enum codecs. Mechanism:
  - circe: auto entry points return `Exported[…]` (circe's low-priority hook; verified in the spike, §7.2).
  - spray-json, play-json, jsoniter (no such hook): the auto entry point's macro first summons the type class for the
    root type **ignoring its own entry point**; if something is found it returns that instance, otherwise it derives.
    Because kindlings and our macros look up field instances through ordinary implicit search, which lands on kebs'
    entry point, the same check makes companion instances win for fields too.
  - Golden tests cover companion codecs, enumeratum `CirceEnum`/`PlayJsonEnum` and Scala 3 `derives`.
  - Behaviour change to list in the migration guide: on **Scala 3**, kebs 2's circe auto-derivation beat companion
    codecs (it sat in lexical scope); in kebs 3 companion codecs win, as they already did on Scala 2.
- Derivation is sanely-automatic where we own the macro (spray, play): the macro tries an implicit first (excluding
  its own entry point), and derives otherwise, recursing internally — recursive types need no `lazy` tricks.
- **Per-field annotations are module-local, with consistent names**: each module has
  `pl.iterators.kebs.<module>.annotations.{fieldName, transientField}`.
  - circe and jsoniter: type aliases to kindlings' annotations (verified: aliased annotations are honoured by
    kindlings on 2.13 and 3.9). jsoniter additionally aliases `named` and `stringified`.
  - spray-json and play-json: one real pair of classes defined in core (`pl.iterators.kebs.core.annotations`) read by
    our macros, aliased into both modules.
- ADT naming of cases uses `constructorNaming`; nested sealed hierarchies are flattened to their leaves (kindlings/
  circe semantics), in all four modules.

Per module:

- **circe** — `KebsCirce` keeps flat/`InstanceConverter` codecs and provides the auto entry point (implicit
  `Exported[Encoder[A]]`/`Exported[Decoder[A]]` for case classes and sealed traits, see §7.2) backed by
  `KindlingsEncoder`/`KindlingsDecoder.derived`,
  with `JsonConfig` translated to kindlings' `Configuration` (`transformMemberNames`, `transformConstructorNames`,
  `useDefaults`, `discriminator`, `unwrapValueClasses = false`). Drops the circe-generic and circe-generic-extras
  dependencies. `NoneHandling.Omit` requires an upstream kindlings change (circe `transientNone`, which its jsoniter
  module already has); until it is available, circe supports only `WriteNull` (today's behaviour) and `Omit` is a
  compile-time error with a clear message.
- **spray-json** — hearth macro generating a `RootJsonFormat[T]` per case class (field-by-field `read`/`write`, no
  22-field limit, no runtime reflection) and per sealed hierarchy. Honors `JsonConfig` and the annotations. Missing
  non-`Option` field without default → `DeserializationException` naming the field (same as spray's `fromField`).
- **play-json** — same macro shape producing `Reads`/`Writes`/`OFormat`; entry points `KebsPlayJson` (identity) plus
  `snakified`/`capitalized` objects like the other JSON modules. Auto-derivation comes with the existing
  `import pl.iterators.kebs.playjson._` / `KebsPlayJson` (decided 2026-11-21, for consistency with circe and spray);
  existing `Json.format` / `PlayJsonEnum` instances keep winning (rule above), covered by golden tests, and the
  migration guide calls out the new behaviour.
- **jsoniter** — `KebsJsoniter` provides flat/`InstanceConverter`/enum `JsonValueCodec`s and an auto entry point backed
  by kindlings' jsoniter derivation, `JsonConfig` translated to `JsoniterConfig` (`withFieldNameMapper`,
  `withAdtLeafClassNameMapper`, `withTransientNone` for `Omit`, discriminator/wrapper, defaults). Platforms JVM+JS+
  Native.

### 5.5 Other modules

- **core `ValueClassLike`** — hearth macro: for a case class with exactly one field, generates
  `new ValueClassLike[T, F](v => T.apply(v), _.field)` (companion `apply`, direct accessor; no casts, no `Tuple1`).
  The field type `F` must be inferred from `T` during implicit search on both versions (whitebox on 2.13; on Scala 3 a
  transparent macro or retaining the `Mirror`-based type evidence while the body is macro-generated — the spike picks).
  Non-case-classes and arity ≠ 1 fail fast and silently (they are implicit candidates in every flat-format search).
- **enum / enumeratum** — `EnumLike`/`ValueEnumLike` instances built from a static list of the cases (enumeratum:
  `Companion.values`; `Enumeration`: `Obj.values.toList`; Scala 3 enums and `ValueEnumLikeEntry` hierarchies: the
  cases in declaration order);
  the name is `entryName` (enumeratum) or the case's simple name. Existing type bounds on the implicits stay, so the
  enum and enumeratum implicits never compete.
- **scalacheck** — `ScalacheckInstancesSupport.arb[T]` delegates to kindlings' `Arbitrary` derivation;
  `KebsArbitrarySupport` keeps its predefined instances and adds enum/`InstanceConverter` ones.
- **doobie** — migrated to doobie 1.0.0-RC14 (`org.typelevel` organisation, `org.typelevel.doobie` package).

## 6. Behavioural spec and testing

- Existing tests are the spec. They move from `scala-2/`/`scala-3/` into shared `src/test/scala` wherever the only
  reason for the split was the macro implementation. Scala-3-only syntax (enums, opaque types) stays in `scala-3/`.
- New tests for every item in §4.2–§4.3 and §5.3–§5.4: naming presets and custom naming, annotations, `NoneHandling`,
  `useDefaults`, ADTs (wrapper and discriminator, nested hierarchies, case objects), recursive types, >22 fields,
  validating `apply` in `ValueClassLike`.
- **Wire-format golden tests**: for circe and spray-json, a fixed set of models encoded with kebs 2.3.0 output is
  checked in as expected JSON; kebs 3 must produce identical JSON with default config. Any deliberate difference goes to
  the migration guide.
- Compile-time regression check: a small benchmark (an existing test module's `Test/compile` time) recorded before and
  after the circe and spray-json PRs, reported in the PR description. No hard threshold.

### 6.1 Raising test coverage (requested 2026-11-21)

- **`kebs-testkit`** — a test-only, unpublished cross-project (JVM/JS/Native) holding shared models and abstract
  contract suites; modules depend on it `% "test->test"`. Created in the build + core PR.
- **Characterisation tests first** — golden JSON (circe, spray-json), enum strings (all enum-aware modules) and flat
  formats are captured from current behaviour in the build + core PR, before any macro is swapped.
- **Contract suites** (each module plugs in its encode/decode or read/write functions):
  - JSON (circe, spray-json, play-json, jsoniter): naming presets + custom, annotations, `NoneHandling`, `useDefaults`,
    ADTs (wrapper, discriminator, nested, case objects), recursion (direct, mutual, generic, through `Option`/`Map`),
    >22 and ~100 fields, flat value classes, `InstanceConverter`, enums, existing instances winning.
  - Enums (circe, spray-json, play-json, jsoniter, doobie, slick, baklava, pekko-http, http4s, http4s-stir,
    pureconfig, scalacheck): `EnumNaming` presets + custom, case-insensitive decoding, unknown values, for enumeratum,
    `Enumeration`, Scala 3 `enum` and value enums.
  - `ValueClassLike` / `InstanceConverter` across all integration modules.
- **Corner cases** (from hearth's derivation checklist): generic types, fixtures from another compilation unit,
  private constructors and validating `apply`, zero-field classes, a user instance in the middle of a recursive
  cycle, derivation inside generic functions.
- **Compile-time tests**: what must not compile, with the error message asserted (missing instance names the type and
  field; no `ValueClassLike` for 2-field classes); stress — 100-field class and 100-case enum compile, no generated
  method exceeds 8000 bytes (class-file `Code` attribute check).
- **Property-based round-trips** (encode→decode = identity) with generators from kebs-scalacheck.
- **Platforms**: shared suites also run on JS/Native for modules published there.
- **Line coverage**: sbt-scoverage, a CI coverage job on JVM for 2.13 and 3.9, reported per module; after 3.0 each
  module's `coverageMinimumStmtTotal` is set just below what it reached (a ratchet). Line coverage cannot see macro
  implementations (they run inside the compiler); for those, the contract suites and corner-case matrix are the
  coverage.
- **doobie / slick value round-trips** against in-memory H2 (no Docker): today's doobie tests only assert that
  `Get`/`Put` instances resolve (0% statement coverage) and slick's mostly that column types resolve (15%), so no
  value is ever actually mapped. Postgres-specific types (slick-pg, doobie-postgres arrays) stay compile-level.
- Out of scope: Testcontainers / a real Postgres.

## 7. Spike results (2026-11-21)

Throwaway sbt project (2.13.18 + 3.9.0, hearth 0.4.5, kindlings-circe 0.4.0); all 9 tests green on both versions.

1. **`ValueClassLike` with inferred `F`: works.** Shared hearth macro (`CaseClass.parse`, single primary-constructor
   parameter, `Expr.quote { new ValueClassLike[T, F](…) }`). Entry points:
   - 2.13: `implicit def repFromCaseClass[T <: Product, F1]: ValueClassLike[T, F1] = macro …` with a **whitebox**
     bundle extending `hearth.MacroCommonsScala2`.
   - 3.9: keep the `Mirror` evidence for inference and candidate filtering, body is the macro:
     `inline implicit def repFromCaseClass[T <: Product, F1](using m: Mirror.ProductOf[T], teq: m.MirroredElemTypes =:= F1 *: EmptyTuple.type): ValueClassLike[T, F1] = ${ … }`.
     A non-transparent inline given is expanded *after* it is selected, so the `Mirror` guard is what keeps non-
     matching types from reaching the macro (a macro abort there would be a hard error, not a skipped candidate).
   - Works through an outer implicit with unknown `A` (`find[T, A](implicit rep: ValueClassLike[T, A])`) and for
     `ValueClassLike[T, ?]`; 2-field case classes get no instance.
   - Cross-quotes gotcha on 2.13: `import field.tpe.Underlying as F` (nested path) breaks `Type.of[…F…]`; bind the
     path first: `val fieldType: ?? = field.tpe; import fieldType.Underlying as F`.
   - The spike constructs with `new T(…)`; the real implementation must call the companion `apply` (§4.2.1).
2. **kindlings circe inside a kebs trait: works, with one required design choice.** kebs' auto entry points must
   return circe's `io.circe.export.Exported[Encoder[A]]` / `Exported[Decoder[A]]` (picked up by circe's low-priority
   `importedEncoder`/`importedDecoder`), exactly like circe-generic's auto derivation. With a plain lexical implicit,
   the imported kebs auto-derivation beats a user's instance in the type's companion. With `Exported`:
   - companion instances win, at the top level and for fields;
   - kebs' flat formats are used for fields (kindlings summons field instances first);
   - recursive types, >22 fields, sealed traits (wrapper) work;
   - entry-point guard: 2.13 macro aborts unless the type is a case class or sealed (candidate skipped); 3.9 uses
     `inline m: Mirror.Of[A]`.
   - **Semantics to keep and document:** with `CaseClass1ToValueClass` in scope, single-field ADT children are flat
     too (`{"Dot":2.0}`), consistent with "every single-field case class is a value class".
   - Nested derived types are expanded through kebs' entry point (one expansion per type, as in classic auto
     derivation) because kindlings ignores only its own implicits. Acceptable; optional upstream improvement in §8.
3. **Aliased kindlings annotations: work** on 2.13.18 and 3.9.0 (`type fieldName = …circederivation.annotations.fieldName`).
4. **kindlings' 3.8.4-built artifacts from 3.9.0: work.**

Consequence for spray-json, play-json and jsoniter: neither library has circe's `Exported` hook, so the auto entry
point's macro summons the root type class ignoring itself and returns what it finds, deriving only when nothing is
found (§5.4). No failure during implicit search is needed, so a plain `inline` entry point with a `Mirror.Of` guard
works on Scala 3. Verify with a spray-json test first in its PR.

## 8. Upstream (kindlings)

- Request: `transientNone`-style option for circe derivation (drop `None` fields when encoding). Needed for
  `NoneHandling.Omit` in kebs-circe; not blocking the release.
- Optional request: a way for a wrapping library to add its own entry points to the implicits kindlings ignores when
  summoning field instances (e.g. a `-Xmacro-settings` key or an annotation), so nested types are derived inside one
  expansion instead of through kebs' entry point. Performance only; not blocking.
- Request: an `unwrapValueClasses`-style switch in kindlings' jsoniter derivation (0.4.0 always encodes `AnyVal` case
  classes as their bare field). Until then kebs-jsoniter documents the exception: `AnyVal` case classes are flat in
  jsoniter even without `CaseClass1ToValueClass`. New module, so no wire-compatibility impact.

**Policy:** kebs 3.0 takes newer kindlings/hearth releases if they land before the release (hearth and kindlings
bumped together, all kebs hearth macros re-tested). Upstream requests never block 3.0: the fallback is a documented
per-module exception, not our own circe/jsoniter macros (writing those would defeat the "less code" goal).

## 9. Left to the builder

- Internal structure of the hearth macros (rules, caching), within the layout in §5.2.
- Exact names of explicit per-type derivation methods (e.g. `deriveEncoder[T](config)`), as long as they are consistent
  across the four JSON modules.
- Whether `-Xmax-inlines`/`-Yretain-trees` can be dropped.
- Error message wording, as long as it names the type and the missing instance.
